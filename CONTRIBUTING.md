# Contributing to Fusion Policy Research

You **do not need to be a programmer** to contribute. This is a research workspace, not a software project.

## Easiest way: GitHub in your browser

1. Open the appropriate folder, such as `qld/`.
2. Select **Add file → Create new file**. Name it something like `accessible-public-transport.md`.
3. Paste your draft. Markdown supports headings (`## Heading`), lists, links and tables.
4. Select **Commit changes**, then choose **Create a new branch and start a pull request** where available.
5. Explain what the paper proposes and what kind of feedback you want. A maintainer can help review and merge it.

You can also upload an existing Markdown file using **Add file → Upload files**. GitHub's interface may vary. If you prefer VS Code, clone the repository, edit locally, commit, push and open a pull request.

## What belongs here?

- Working papers, evidence reviews, alternative options, feasibility studies and policy critiques.
- State-specific work in `qld/`, `vic/` and cross-jurisdictional work in `national/`.
- Source data, diagrams and supporting notes where attribution and permission allow.

Start with the [research template](templates/research-brief.md), but don't let formatting delay a substantive first draft.

## Review process

1. **Draft:** author states the question, evidence, assumptions and uncertainties.
2. **Review:** contributors challenge factual claims, costs, trade-offs, implementation and rights implications.
3. **Revision:** author responds to findings and records significant changes.
4. **Publication:** maintainers may merge research here. **Merging is not party endorsement.** Formal adoption happens through the relevant party process.

Prefer specific, actionable feedback over agreement or dismissal. Critique arguments, not authors. Preserve differing assessments when evidence remains contested.

## Naming and housekeeping

Use lowercase, hyphenated filenames; keep a single topic per paper where practical. Put local supporting assets in a nearby `assets/` directory. Do not commit personal information, passwords, private correspondence or copyrighted material without permission. Cite external material rather than copying it wholesale.

If you're unsure how to use GitHub, open an issue or ask a maintainer for help.
